## Architecture

- **Shell:** Tauri v2 (Rust) in `apps/desktop/src-tauri`.
- **Frontend:** React + TypeScript + Vite, Tailwind CSS v4, in-repo shadcn/ui-style components, Zustand, in `apps/desktop/src`.
- **Bridge:** Node sidecar in `packages/bridge`. Providers sit behind the `Provider` interface (`src/providers`): Claude (the Agent SDK on the user's Claude Code login), ChatGPT (the official Codex CLI) and Grok (xAI API key or the Grok CLI). **Claude never takes an API key.** Other providers take one only where `docs/providers.md` says an API key is an official route.
- **Protocol (v4):** `packages/protocol` holds the shared TS types, validating parsers and NDJSON helpers. Source-only (no build step). Transport is newline-delimited JSON over the sidecar's stdio; stdout is protocol only, stderr is logs. Requests: `ping`, `chat` (optionally `provider` and a per-request `apiKey`), `cancel`, `usage`, `providers` (answered by one `providers.report`) and `provider.login` (opens the provider's own CLI sign-in in a terminal, then answers with a report). A `chat` is answered by `chat.text` / `chat.tool_use` / `chat.tool_result` / `chat.rate_limit` / `chat.limits` events (all carrying the request `id`) and exactly one terminal event: `chat.done` (`completed` or `cancelled`, with the reply's per-model token usage) or `error` (structured `code`, plus `resetsAt`/`limitType` for limits). `usage` is answered by one `usage.report` (plan windows, subscription type, extra usage). Bump `PROTOCOL_VERSION` on any breaking change.
- **Process wiring:** Rust (`src-tauri/src/bridge.rs`) spawns the bridge (see Packaging below for which one), exposes `bridge_start` / `bridge_send` commands and re-emits each stdout line as a `bridge://line` event. Rust treats lines as opaque; the UI parses them with `BridgeClient` (`src/lib/bridge.ts`).
- **Persistence:** SQLite via `tauri-plugin-sql`. Migrations in `src-tauri/migrations`, registered in `src-tauri/src/lib.rs`. Tables: `conversations` (title, pinned, model, system prompt, tools mode, cwd, project, attached library system prompt and its variable values), `messages` (role, content, attachments JSON, status `complete|stopped|error`, error JSON, model, token, cache and cost fields), `prompts` (kind `prompt|system`, title, tags JSON, body), `projects` (name, default system prompt and its variable values), `usage_log` (one row per reply per model) and `usage_windows` (latest plan window readings). All SQL lives in `src/lib/repo.ts`, written with `?` placeholders; the Tauri adapter in `src/lib/db.ts` renumbers them to `$1..$n` as the plugin documents. Search is `LIKE` over titles and message content.

### Code tools design decisions

- **Highlighting:** Shiki with its JS regex engine (no WASM), a **CSS-variables theme**, and a curated list of grammars in `lib/highlight-core.ts`, each a lazy chunk. Token colors are `var(--shiki-*)`; the light/dark values live in `styles/index.css`, so a theme switch recolors every block with no re-highlighting. Tokenizing runs in a Web Worker (`highlight.worker.ts`, ES module worker, per-block channels so stale requests are dropped); `highlight.ts` falls back to in-thread highlighting where `Worker` does not exist (unit tests). To support a language, add one loader line to `LOADERS` (and aliases in `fence.ts`). Never highlight on the main thread: it caused 100–300 ms hitches while streaming.
- **Code blocks** (`components/code/CodeBlock.tsx`): each block has a stable key `messageId:blockIndex:fenceLine`. `StreamState.messageId` is generated when a reply starts and reused as the stored message's id, so keys survive the streaming-to-stored hand-off. Fence info supports `title="a.ts"`, `filename=a.ts`, `ts:a.ts` and a bare path (`lib/fence.ts`).
- **Diffs:** `lib/diff.ts` parses unified diffs leniently (wrong hunk counts, missing context spaces, no `@@` headers are all tolerated; a hunk's `--- x`/`+++ y` pair is a file header only when a `@@` follows) and builds one model for the inline and side-by-side views; word-level highlights come from the `diff` library for paired removed/added lines. `DiffView` falls back to inline below 520 px. The diff library is lazy (`DiffBlock`, `DiffTab` are `React.lazy`).
- **Preview isolation (security-critical):** previewed HTML is untrusted. It runs in an iframe with `sandbox="allow-scripts"` only (never add `allow-same-origin`, `allow-popups`, `allow-top-navigation`, `allow-forms` or `allow-modals`). In the desktop app the document is registered with Rust (`preview_set`) and loaded from the custom `preview:` scheme (`src-tauri/src/preview.rs`, `http://preview.localhost` on Windows), which serves it with its own CSP header (`default-src 'none'`, scripts and styles allowed, `connect-src 'none'`, plus `sandbox allow-scripts`). A `srcdoc` iframe would inherit the app's CSP and could not run scripts. The page is a different origin with an opaque sandbox origin, so it cannot read the app, its storage or the bridge, and the Tauri IPC rejects it because no capability grants `remote` URLs (do not add one). `PREVIEW_CSP` is duplicated in `lib/preview-doc.ts` and `preview.rs`; a test enforces they match, and the e2e harness reads the Rust constant. The app CSP gained `frame-src preview: http://preview.localhost https://preview.localhost`. Console output arrives by `postMessage` and is accepted only from the frame's own `contentWindow` with its per-build id (`parseConsoleMessage`). Mermaid renders to SVG in the app (`securityLevel: 'strict'`), and the SVG is then shown inside the same sandbox. Markdown previews reuse the safe `Markdown` component (no raw HTML) with no iframe.
- **Preview tabs** live in `stores/preview.ts` (max 8). A tab opened from a block follows it by `sourceKey`: while the reply streams, `CodeBlock` pushes new code into the tab after a 250 ms debounce, which re-runs the page and clears its console.
- **Save as file** uses the native save dialog plus `plugin-fs` `writeTextFile`; paths picked in the dialog are added to the fs scope, and only `fs:allow-write-text-file` is granted. In a browser it downloads instead.
- **Shortcuts** are defined once in `lib/shortcuts.ts` (handler and help dialog share the table): copy last code block `Mod+Shift+C`, toggle preview `Mod+Shift+P`, toggle diff mode `Mod+Shift+D`, toggle sidebar `Mod+B`, help `Mod+/`. A shortcut may set `macKeys` when its combination is a macOS system shortcut (the QA panel is `Mod+Shift+Y` there, because Cmd+Shift+Q logs out); tooltips use `shortcutLabel()` (⇧⌘C on macOS, in Apple's modifier order, Ctrl+Shift+C elsewhere), never a hard-coded "Ctrl". Matching is exact about modifiers (no Alt, to stay clear of AltGr layouts).

### macOS design decisions

- Details and the full table live in `docs/macos.md`. In short: native traffic lights through `tauri.macos.conf.json` (Tauri merges it only on macOS, so Windows/Linux config is unchanged) and `lib/window-chrome.ts` (`usesNativeTitleBar`: `WindowControls` hides, toolbars keep `NATIVE_LIGHTS_INSET` free); the standard app menu with Settings ⌘, (`system.rs` `build_app_menu`, event `command-center://settings`); a template tray icon (`scripts/tray-icon.mjs`); the Dock icon reopens a window hidden to the tray (`RunEvent::Reopen`).
- **Sign-in terminals** on macOS run `/usr/bin/osascript` directly with argv (no shell): the command is POSIX single-quoted, then escaped as an AppleScript string (`shellQuote`, `appleScriptString`); iTerm when `TERM_PROGRAM` says so, Terminal.app otherwise. Linux still throws the instructions.
- **GUI PATH:** `resolveCommand` on macOS calls `ensureGuiPath(env)` once, which extends `env.PATH` in place with the login shell's PATH (`$SHELL -ilc`, 3 s timeout, cached, output between markers) plus Homebrew, user bins, npm, volta, fnm and nvm folders. In place on purpose: children spawned with the same env (npm shims with `#!/usr/bin/env node`) need it too.
- **Keychain:** on macOS the one-time API-key copy runs on a thread after the window opens and the key commands wait on `KeysReady` (up to 30 s); a failed read there is final (marker lists it as skipped) so a denied prompt is not repeated every launch.
- **Bundled binaries** are ad-hoc signed and de-quarantined by `prepare-sidecar.mjs`, which picks the runtime for the target triple's CPU and refuses a mismatched Node.
- **Mermaid** is imported lazily on first use; its large diagram-type chunks load only when that diagram type is rendered.

### Chat design decisions

- **The app owns history; the bridge is stateless.** Every `chat` request carries the full transcript (SQLite is the source of truth). The bridge replays prior turns as a transcript inside the prompt (`packages/bridge/src/prompt.ts`, oldest turns dropped above ~400k chars) and runs a fresh, non-persisted query (`persistSession: false`, `settingSources: []`). This is what makes edit, regenerate, model switching and stopped replies trivial and keeps `~/.claude` clean. Trade-off: tool results from earlier turns are not carried forward, and there is no server-side session to resume.
- **Tools are opt-in per conversation.** `off` (default): `tools: []`, one turn. `readonly`: only Read/Glob/Grep in the chosen folder, `permissionMode: 'dontAsk'` so anything else is denied instead of prompting (there is no permission UI yet). No edit or shell tools exist in the app; adding them needs a permission-prompt UI first.
- **Subscription only.** `runtimeEnv()` strips `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` from the runtime's environment so a stray key can never silently switch billing. Never add API-key handling. Without tools the runtime runs in `os.tmpdir()` so it does not leak the app's own path to the model.
- **Errors are structured.** The bridge maps SDK errors (`authentication_failed`, rate-limit info, thrown text) to protocol codes in `errors.ts`; the UI turns codes into friendly copy in `src/lib/errors.ts`. Raw messages only appear under "Details" for unexpected errors. The SDK reports `resetsAt` in unix seconds; `normalizeResetsAt` converts to ms.
- **Streaming UI.** `chat` store buffers deltas and flushes once per animation frame (every 100 ms past 12k chars). Markdown is split into top-level blocks (`markdown-blocks.ts`) and each block is memoized, so only the last block re-parses. Code highlighting uses one shared lowlight instance (`rehype-lowlight.ts`); `rehype-highlight` rebuilds its grammars on every render and must not be reintroduced. The transcript is virtualized with `@tanstack/react-virtual`.
- **Zustand v5 selectors must return stable references.** A selector that builds a new object (like `selectActiveSettings`) must go through `useShallow` (see `useActiveSettings`) or React loops forever.

### Packaging and release design decisions

- **Three pieces ship with the installer**, assembled by `scripts/prepare-sidecar.mjs` (run by `tauri build` through `beforeBuildCommand`; everything it writes is git-ignored): the Node runtime as a Tauri external binary (`binaries/node-<triple>[.exe]`, installed beside the app as `node[.exe]`), the bridge with the Agent SDK **bundled into one file** (`pnpm --filter @command-center/bridge build:release` to `resources/bridge/main.mjs`), and the SDK's native Claude runtime (`claude[.exe]`, copied from the matching `@anthropic-ai/claude-agent-sdk-<platform>-<arch>` package, about 250 MB, so the installer is large). The bridge is told where the runtime is through `COMMAND_CENTER_CLAUDE_EXECUTABLE` (`claudeExecutable()` in `sdk.ts`, applied in `buildOptions` and the usage request), so it never searches `node_modules` at run time. Dev builds keep `--external` and the SDK's own lookup.
- **Lite flavour:** `pnpm sidecar --lite` or `COMMAND_CENTER_LITE=1` (read by `prepare-sidecar.mjs` through `beforeBuildCommand`) bundles only the bridge: `node` and `claude` are empty stand-ins plus a `resources/bridge/lite` marker. `bridge.rs` `lite_launch` then finds the installed `node` and `claude` on `gui_path::search_path()` (current PATH, the login shell's PATH read with a 3 s process-group timeout, and the usual install folders) and passes that PATH and `COMMAND_CENTER_CLAUDE_EXECUTABLE` to the bridge, or fails with what to install. Releases stay full.
- **Bridge lifecycle:** not started at launch (`App.tsx` no longer connects; `Boot` does not wait for it). `useBridgeStore.connect()` / `ensureBridge()` start it on the first chat, provider check, sign-in or usage request. `BridgeClient.onSettled` restarts an idle countdown after each finished request; after `prefs.system.bridgeIdleMinutes` (0 = never, default 10) with nothing in flight the store calls `bridge_stop` (closes stdin, kills after 1 s) and an intentional stop is not reported as a crash.
- **Launch resolution** (`bridge.rs`): `COMMAND_CENTER_BRIDGE_ENTRY` or a debug build runs the workspace bundle with the `node` on PATH; a release build runs `<exe dir>/node` on `<resource dir>/bridge/main.mjs` and fails with a message naming the missing piece ("Reinstall Command Center"). Covered by Rust unit tests on a scratch layout.
- **tauri-build needs the sidecar files to exist** even to compile: CI's Rust job and `tauri dev` run `node scripts/prepare-sidecar.mjs --placeholder` to create empty stand-ins. Never ship a build made from placeholders.
- **Login is the user's, not ours.** The installed app reads the Claude Code login from the user's profile exactly as the CLI does. Nothing about credentials is bundled or stored, and `runtimeEnv()` still strips API-key variables.
- **Release flow** (`.github/workflows/release.yml`): a `vX.Y.Z` tag (or a manual run, which publishes nothing) checks that the tag matches every manifest (`scripts/release-tools.mjs check-version`), runs `pnpm check`, builds the NSIS installer, installs it silently into a temp dir, runs `scripts/smoke-installed.mjs` (finds node/main.mjs/claude, runs `claude --version`, pings the bundled bridge), launches `command-center.exe` and requires its child `node.exe` to be running the installed `main.mjs`, then publishes with the matching CHANGELOG section (`release-tools.mjs notes`) as the release body plus `SHA256SUMS.txt`. A parallel `macos` job (`macos-14`) builds an unsigned dmg, installs the app from it, runs `smoke-installed.mjs` (which also verifies the ad-hoc signatures), launches it and requires its bundled `node` on the bundled `main.mjs`; on tags `publish-macos` attaches the dmg and `SHA256SUMS-macos.txt` to the release the Windows job created. The release is created by the workflow's token, so GitHub lists the Actions bot as publisher; the notes carry no tool attribution. To release: update CHANGELOG.md and all four version fields, merge, tag `vX.Y.Z` on main as milesceo, push the tag.
- **Settings and data:** `stores/settings.ts` (interface zoom via CSS `zoom`, `--code-font-size`, default model and system prompt for new chats) lives in localStorage; chats and everything else are in SQLite. `lib/data.ts` exports and clears tables (clearing prompts/projects nulls the references on conversations first). The data folder comes from the `data_location` Rust command (`app_config_dir`, where the SQL plugin keeps the database).
- **Command palette** (`components/palette`, `lib/commands.ts`): pure ranking in `lib/commands.ts` (prefix > word start > substring > subsequence); commands are built from live stores each time it opens; the variables form of an inserted prompt is hosted outside the open check so it outlives the palette.
- **Accessibility:** `e2e/a11y.mjs` runs axe-core (WCAG 2 A/AA plus best practice) over every view in both themes and must report nothing serious. `--fg-subtle` is tuned to 4.5:1 on every surface; keep it that way when adding tokens. Modal surfaces use `useFocusTrap` (trap Tab, restore focus on close).

- **Rename and data migration:** the app has had two earlier names before Command Center (their identifiers, database names and credential service are constants in `migrate.rs` and `legacy_keys.rs`). The bundle identifier changed each time (now `com.milesceo.commandcenter`), which moves the config folder (SQLite, `lock.json`, `system.json`) and the webview profile (localStorage: WebView2 under the local data folder on Windows, `~/Library/WebKit/<identifier>/WebsiteData` on macOS). The window is therefore created in `setup` (`"create": false` in `tauri.conf.json`) after `src-tauri/src/migrate.rs` has copied the **newest** earlier install's data (the migrations are chained by picking a source: the newer install wins because it already holds what it migrated; an install with a database beats an empty newer folder): the database (+ `-wal`/`-shm`) to `command-center.db`, the Rust config files, and the webview storage. Every copy goes through a temporary name, is compared byte for byte (and the source must be unchanged), and only when every file verified are they moved into place (all or nothing), then `migrated-from-previous-name.json` is written. On Windows a still-running previous version (its files held open) stops the copy first. If the migration fails, a native message box before any window exists offers Quit (retry after closing the old app) or Start without old data (marker status `skipped`), because opening the app on an empty profile would make a retry impossible. A conflicting destination is never overwritten; the old data is never modified or deleted. API keys are copied once from the old credential-store service by `legacy_keys::migrate_legacy_keys_once` (read old, write new, read back and compare, a bad copy is removed; marker `migrated-keys-from-previous-name.json`; old entries left intact). `src/lib/legacy.ts` copies the old `localStorage` keys to their `command-center-*` names (imported first from `main.tsx`; the newer name wins; runs once per profile, flag `command-center-legacy-copied`, so a PIN record removed later never comes back; `lock-backend.ts` also drops the old localStorage record whenever Rust holds a PIN or the PIN is removed) and keeps accepting prompt-library files exported under both earlier format names. The previous environment-variable prefix still works for one release with a stderr warning (`packages/bridge/src/env.ts`, `src-tauri/src/env.rs`; an empty value counts as unset). The old names may appear only in those files, the CHANGELOG, `docs/prompts/` and the upstream and status-feed repository URLs (plus the feed schema's own field name); `scripts/check-name.mjs` (part of `pnpm check`) enforces that.

### Usage and prompt library design decisions

- **Usage comes from the SDK result, never from estimates.** `usageFromResult` (bridge `usage.ts`) prefers `result.modelUsage` (per model, with `costUSD`) and falls back to `result.usage` for the model the run used. The desktop writes one `usage_log` row per reply per model right after `chat.done`. `usage_log` has no foreign keys on purpose: deleting or regenerating a message must not erase what was used. Replies the user stops part-way carry no usage (the SDK sends none), so they are not counted. Older rows written before phase 4 store `input_tokens` as the SDK's uncached input only.
- **Cost is "API-equivalent cost".** It is the SDK's `costUSD` list-price figure, informational on a subscription, never a bill. Always use `COST_LABEL`/`COST_NOTE` from `lib/format.ts`; never call it "spend" or "cost" alone.
- **Plan headroom is shown only when the SDK reports it, and never extrapolated.** Two sources: `rate_limit_event.rate_limit_info.unifiedWindows` (untyped in the SDK types but observed; fractions, `resetsAt` in unix seconds) arrives before each result as `chat.limits`, and the experimental `Query.usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` (percent, ISO time) answers the `usage` request. Both are parsed defensively. A login without them (API key, third-party provider, or a container without profile access) shows "not available" instead of a guess. A reading from before the window's last reset is flagged out of date.
- **Charts** (`components/usage`): hand-built SVG stacked bars following the dataviz rules (bars <= 24 px, 4 px rounded data end, 2 px gaps, legend that toggles series, text in text tokens, table view, hover tooltip, one validated palette `--series-1..4`). Day/week bucketing is done in SQLite on local time with Monday-based weeks.
- **Prompt library:** `prompts` rows are either `prompt` (inserted into the composer) or `system` (attached to a conversation or a project). `{{name}}` variables are extracted by `lib/prompt-vars.ts`; a prompt with variables opens `VariablesForm` first. A library system prompt is stored by reference plus variable values and rendered at send time (`lib/system-prompt.ts`: custom conversation text > attached library prompt > project default), so editing it updates every chat using it. The composer's `/` menu (`lib/slash.ts`, `SlashMenu`) searches prompt-kind rows. Export/import is a versioned JSON file (`command-center-prompts` v1, `lib/prompt-library.ts`); import merges by id (newer wins) and skips identical duplicates.
- **Projects** are a flat grouping of conversations with an optional default system prompt; deleting one ungroups its chats.
- **Selectors must be referentially stable** (this bit twice again: `?? []` and `.filter()` inside a `useStore` selector). Select the raw value and derive it with `useMemo`/a module constant.

### IDE shell and app lock design decisions

- **The default layout is an editor-style shell** (`apps/desktop/src/ide`): floating rounded panes on a dark canvas, a unified toolbar with a command pill, an icon rail, a frosted explorer (threads grouped by project, plus the open thread's files), a tabbed editor with breadcrumbs, the conversation docked on the right as the assistant, an optional activity panel and a status bar (`ide/shared/Hud.tsx`). The original sidebar layout is untouched and stays one setting away (`ui.layout`: `ide` | `classic`, palette command "Use classic layout"); the older e2e scripts and the App tests drive the classic one. Usage, Prompts and Settings open as views in the editor area.
- **Files are derived, not stored.** `ide/shared/files.ts` groups a thread's code blocks into files with versions (same file name first, else the most similar earlier block of the same language, the heuristic behind "compare with earlier version"). Nothing is written to disk and no tool can edit the user's files; that still needs the permission UI.
- **The app lock is a screen lock, not encryption.** `lib/app-lock.ts` (pure, tested) stores a 4 to 8 digit PIN as a salted PBKDF2-SHA-256 hash (150k iterations) in localStorage (`command-center-lock`); `stores/lock.ts` owns the phase (`setup` | `locked` | `unlocked`), the idle timeout and the lockout (5 free attempts, then 30 s doubling to 5 min, persisted so a restart does not reset it). The chat database is NOT encrypted; never describe the lock as encryption. `LockGate` renders nothing of the app while locked, so no conversation text is in the DOM behind it. First launch asks the user to choose a PIN twice and offers an explicit "continue without a PIN". A forgotten PIN cannot be recovered: the only way back in erases the PIN and all local data (`clearData(db, 'everything')`) after typing DELETE.
- **The landing page is generated text.** `lib/ascii-field.ts` is a pure, deterministic frame generator (a plasma field plus a 5x5-pixel wordmark); `AsciiBackdrop` writes frames straight into two `<pre>` elements at 24 fps (no React state, no per-frame render) and paints one still frame under `prefers-reduced-motion`.
- **e2e harness:** `launch({ layout, lock })` defaults to `classic` and `skip` so older scripts keep working; `e2e/ide.mjs` captures the shell and the lock flow.

### Onboarding, preferences and providers design decisions

- **One settings schema** (`lib/prefs.ts`): typed defaults, `normalizePrefs` (field-by-field repair) and versioned `MIGRATIONS` (index N upgrades N to N + 1; never edit a shipped one). `stores/prefs.ts` persists it in localStorage (`command-center-prefs`) and imports the older stores' values once. Secrets never live in it.
- **Everything the tier slider controls is in `lib/performance.ts`** (`TierFlags`, `TIERS`, `summarizeTier`). WIRED flags have a consumer; TODO flags (`highlightDepth`, `backgroundIndexing`) are stored and shown and marked in that file. Effective animation is the user's setting (default: follow the OS) capped by the tier (`effectiveMotion`). `lib/apply-appearance.ts` writes theme, palette tokens, `data-motion`, `data-density`, `data-glass` and `data-tier` onto `<html>`; `styles/index.css` consumes them. `ui.theme` is only the _resolved_ theme. **The tier in effect** is `effectiveTier(chosen, power, prefs.performance.followPower)`: on macOS the `power` store polls `system_power_state` (`pmset`) once a minute and the tier is capped at Light on battery and Lightest in Low Power Mode; `useEffectiveTier()` is what `use-appearance`, `AsciiLogo` and `AsciiBackdrop` read (never `prefs.performance.tier` directly). Animations run on timers at the tier's frame rate (no requestAnimationFrame spin) and pause on `visibilitychange` (hidden, minimized or occluded).
- **The PIN is hashed with Argon2id in Rust** (`src-tauri/src/lock.rs`): the PHC string, failure counter and lockout deadline live in `lock.json` in the config directory, so delays survive restarts and cannot be reset from webview storage. 4 to 8 characters, any non-control characters. Failures: 5 free, then 30 s doubling to 5 min. `lib/lock-backend.ts` hides Rust vs the browser fallback (PBKDF2, tests and `dev:web` only) and upgrades a pre-Argon2 record on first successful unlock. "Forgot PIN" wipes the PIN, API keys, all chat data and prefs, then reloads into onboarding. It is a screen lock, not disk encryption. The PIN field is `components/pin/PinCircles`: eight circles are the input, typing goes to a visually hidden but focusable `<input>` (paste, Backspace and screen readers work; focus is kept on it), slots 1 to 4 mark the minimum, Enter submits, and an eye button reveals the characters (off by default, off again whenever the screen is left).
- **API keys live in the OS credential store** (`src-tauri/src/secrets.rs`, `keyring`), service `command-center`, user `api-key:<provider>`. The webview reads one only to attach it to a single chat request. Never write a key to SQLite, localStorage, files or logs.
- **Tray and close behavior** are Rust (`src-tauri/src/system.rs`): the close choice is kept in `system.json` and applied by the window-event hook; the tray menu (Open, New chat, Lock, Quit) emits `command-center://*` events the app listens to (`lib/system.ts`). Hiding to the tray also locks the app. Autostart is `tauri-plugin-autostart` and its state is read back from the OS, not trusted from prefs.
- **Splash and Home**: the first frame is a static ASCII logo embedded in `index.html`; `main.tsx` renders `Boot` (a tiny chunk) with the splash and loads `App` behind it. The splash shows the spinning logo (`components/splash`, minimum 900 ms, cap 8 s, until the PIN state is read; the bridge is not waited for, it starts on first use) and then hands off to the PIN lock inside the app. The spinning 3D logo (`lib/ascii3d.ts`: extruded voxel surface points, rotation about Y with a slight tilt, perspective, depth buffer, Lambert shading onto a luminance ramp) lives only on the splash: frame rate follows the tier, still at Lightest or with animations off, paused while hidden. Home (`components/landing`) shows the same logo as one still frame in the top-left, the Command Center mark and a launch line from `lib/launch-messages.ts` (data file, weighted, never the previous launch's id, stat lines only when there is data). Measured cost is in the PR that introduced it.
- **Chats store `provider` and `model`** (migration 0004). The picker lives in the chat headers (`ProviderModelPicker`). Changing provider resets the model.

### AI status feed (companion repo)

- **`engineerlish/geeked-ai-status`** is a separate public repo (not a fork) with a scheduled workflow (`*/30 * * * *`) that snapshots each provider's models (their official models-list endpoints, with API keys held as Actions secrets there) and service status (Statuspage JSON for Claude and ChatGPT; xAI's incident RSS, the fragile one) and commits to its `main` **every run, changed or not**, authored as engineerlish through the noreply address. It writes `latest.json`, `history/YYYY/MM/DD/HHmm.json` and `history/INDEX.md` + `index.json`, and publishes `schema.json`. Its README documents sources, the schema and growth.
- **The app reads only `latest.json`** from `https://raw.githubusercontent.com/engineerlish/geeked-ai-status/main/latest.json` (the one extra `connect-src` host in the CSP). `packages/protocol/src/status-feed.ts` mirrors the schema (field names are the feed's own, snake_case) and `parseStatusFeed` validates it: a newer `schema_version` or a malformed provider is refused or dropped, never trusted. `stores/status.ts` loads the cached copy first, then fetches on launch and every 30 minutes (and when the browser comes back online) and keeps the last good copy when offline (`lib/status-feed.ts`).
- **Status dots** (`components/status/StatusDot`) sit in the chat header picker and on the Settings AI agents cards; hover shows the summary, click shows incidents with links. **New models**: the first time a provider is seen its list is a silent baseline; afterwards a new chat-capable id for a _connected_ (enabled) provider produces one dismissible notice and is added to that provider's model picker (`mergeModels`). Embedding, speech and image ids are never announced.
- The feed repository belongs to the upstream author and keeps its name; the owner may fork it later and point the URL (CSP `connect-src`, `lib/status-feed.ts`, `protocol/status-feed.ts`) at the fork.
- The status repo is a data source, not a dependency: with no network and no cache the dots are grey and everything else works. Never let a feed value reach a shell, a URL other than an `http(s)` link the user clicks, or HTML.

## Subagents

Four project subagents live in `.claude/agents/` (Claude Code's documented format: Markdown with YAML frontmatter; the description drives delegation). They are development helpers for building Command Center, not an app feature. Call them by name ("use the reviewer subagent") or `@"reviewer (agent)"`.

| Agent         | Use it                                      | Can do                                                                                                               |
| ------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **reviewer**  | After each meaningful change, before commit | Read-only. Bugs, edge cases, security, performance, patterns, snippet-style output. must-fix / should-fix / nitpick. |
| **ui-polish** | After any UI change, with the reviewer      | Read-only. Tokens, themes, a11y, keyboard, focus, empty/loading/error states, motion setting, performance tiers.     |
| **tester**    | Before a feature is marked done             | Edits **test files only**; runs Vitest, cargo test and the e2e scripts; reports app bugs as a failing test + cause.  |
| **regulator** | Before every commit and every push          | Edits **Markdown docs only**; verdict `PASS` or `BLOCKED` with numbered violations citing rule and source.           |

Workflow for every session:

1. **Before writing code:** save the session prompt, verbatim, to `docs/prompts/YYYY-MM-DD-topic.md` as the **first commit of the branch** (`docs/prompts/README.md`).
2. **After each meaningful change:** run the **reviewer**, plus **ui-polish** for any UI change.
3. **Before marking a feature done:** run the **tester**.
4. **Before every commit and every push:** run the **regulator**. Nothing is pushed until it returns PASS.
5. **Fix every must-fix finding before moving on.** Should-fix items you defer go in the PR description.
6. **Read-only subagents stay read-only.** The main agent applies all fixes (the tester writes tests, the regulator fixes docs; everything else is the main agent's), so there are never conflicting edits. Run subagents one at a time on the same files.

Rule hierarchy the regulator enforces, highest first: (1) the current session's prompt, (2) this file, (3) prompts in `docs/prompts/` (newer overrides older), (4) other `docs/*.md` and established conventions in the code.

Design decisions:

- **Permissions are enforced by tool lists and a hook, not only by instructions.** Subagent frontmatter can only allow or deny a whole tool (`Bash(git diff *)` in `tools` does not narrow Bash), so each agent's `PreToolUse` hook runs `.claude/hooks/agent-guard.mjs <profile>`: read-only agents get Bash limited to inspection commands (`git diff|log|show|status`, `gh pr view|diff`, `ls`, `cat`, `grep`, ...); the tester adds the project's test commands and may edit only test files; the regulator adds the generated-doc guards and may edit only Markdown (never the generated `docs/TESTING.md`). No profile can commit, push, install or redirect output, and none can edit `.claude/` (its own definitions). The hook fails closed (any error blocks) and is covered by `scripts/agent-guard.test.mjs`, which runs in `pnpm test`. Accepted limit: the tester can write and run test scripts, so the guard catches drift, not a determined agent. When a command or path a role legitimately needs is blocked, change the guard and say so in the PR; do not work around it.
- **Rust unit tests are inline** (`#[cfg(test)]` in `src-tauri/src`), which the tester may not edit; it writes `src-tauri/tests/` integration tests where it can and reports the rest as a coverage gap.
- Agents cite this file and `docs/` rather than restating it, so when a convention changes here, the agents pick it up. If an agent's instructions mention a script, folder or command, keep them in sync when you rename it.
- The agent files are picked up within seconds when `.claude/agents/` already exists; a session started before the folder existed needs a restart.

## Conventions

- TypeScript strict (plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`). Small typed modules; write complete files; comments explain why.
- Style via design tokens only (`bg-surface`, `text-fg-muted`, ...); dark is default, light via `[data-theme='light']`. Restrained, Linear/Raycast-like: subtle borders, tight spacing, no decorative gradients. Fonts: Geist (UI) and Geist Mono (code), bundled locally.
- Protocol changes start in `packages/protocol` with tests. Never edit a shipped SQL migration; add a new one.
- Keep the SQL capability list in `src-tauri/capabilities/default.json` minimal.

## Commands

`pnpm install`, `pnpm dev` (Tauri), `pnpm dev:web` (browser UI only), `pnpm check` (format + lint + typecheck + test), `pnpm build`, `pnpm rust:fmt`, `pnpm rust:lint`. Not in CI (needs Chromium; set `E2E_CHROMIUM` if it is not under `/opt/pw-browsers`): `pnpm --filter @command-center/desktop e2e` runs the browser end-to-end suite against a fake SDK (`E2E_REAL=1` uses the real Claude runtime and your login), and `E2E_PROD=1 node apps/desktop/e2e/perf.mjs` (after `pnpm build`) checks streaming frame times on the production build (budget: p95 frame <= 70 ms and no task over 150 ms at ~500 tokens/s). CI (`.github/workflows/ci.yml`) runs the JS checks on Ubuntu and `cargo fmt`/`clippy`/`test` on Ubuntu, Windows and macOS (`macos-14`, Apple Silicon). The release workflow also builds an unsigned dmg on `macos-14`, installs it from the dmg, smoke-tests and launches it, and attaches it on tags (`publish-macos`).

Usage tokens/cost were verified against a real SDK reply.
- Replies stopped part-way have no usage (the SDK sends none) and are not counted.
- Search is `LIKE` (fine for personal volumes); move to FTS5 if it gets slow.

Their behavior inside the real WebView2 window is unverified: check preview, console output and save on first Windows launch.
- Diff lines are not syntax highlighted (only changed words are marked). The preview iframe reloads on every update, so scroll position resets while a reply streams.
- Code blocks inside list items are matched to previews by line number, which is stable while streaming but would change if the model rewrites earlier text.
